# Guil‑OS — Architecture Modulaire RISC‑V  
Système d’exploitation minimaliste, distribué, et entièrement piloté en assembleur RISC‑V.

## 📌 Introduction  
**Guil‑OS** est un micro‑système d’exploitation conçu pour fonctionner comme le **cerveau central** d’un ensemble de cartes électroniques modulaires.  
Chaque carte (audio, écran, stockage, USB, PCMCIA, etc.) possède son propre microcontrôleur et communique avec Guil‑OS via des bus simples (SPI, UART, I²C, GPIO parallèle).

L’objectif :  
- un OS **ultra‑léger**,  
- **entièrement en assembleur RISC‑V**,  
- **temps réel**,  
- **hautement modulaire**,  
- capable de piloter un rack informatique complet.

---

# 🧠 Philosophie du Projet  
Guil‑OS repose sur trois principes :

### 1. **Simplicité absolue**  
Le noyau est écrit en assembleur RISC‑V.  
Pas de couches inutiles. Pas de POSIX. Pas de Linux.  
Juste un timer, un scheduler, un framebuffer, et un moteur isométrique.

### 2. **Modularité totale**  
Chaque fonctionnalité lourde (audio, USB, stockage, réseau, PCMCIA…) est déportée sur une carte dédiée.

### 3. **Communication claire**  
Les cartes échangent des messages simples :  
- événements (clavier, souris, audio terminé)  
- commandes (jouer un son, charger un fichier, dessiner un sprite)  
- blocs de données (tiles, sprites, fichiers)

# ⚙️ Guil‑OS : Noyau RISC‑V en Assembleur

## Timer  
- Interruption toutes les X ms  
- Déclenche le scheduler  
- Gère les animations du moteur isométrique  
- Déclenche les scans clavier (si GPIO matrix)

## Scheduler  
- Round‑robin ou priorité fixe  
- Contexte minimal :  
  - registres  
  - pointeur de pile  
  - état (RUNNING, READY, SLEEPING)

## Gestion GPIO  
- Accès direct aux registres mémoire  
- Fonctions en assembleur :  
  - `gpio_set(pin)`  
  - `gpio_clear(pin)`  
  - `gpio_read(pin)`  
- Support pour bus parallèle (PCMCIA, VGA, etc.)

## Gestion Audio (via Carte Audio)  
- Guil‑OS envoie :  
  - `PLAY(track_id)`  
  - `STOP(channel)`  
  - `SET_VOLUME(value)`  
- La carte audio renvoie :  
  - `AUDIO_DONE(channel)`

## Gestion Écran (via Carte Écran)  
- Guil‑OS envoie :  
  - blocs framebuffer  
  - commandes de dessin (tile, sprite, texte)  
- La carte écran gère :  
  - synchro  
  - DMA  
  - double buffering

## Moteur Isométrique 2D  
- Projection iso :  
  ```
  x = x0 + (i - j) * (T/2)
  y = y0 + (i + j) * (T/4)
  ```
- Blitting en assembleur  
- Tiles préchargés depuis la carte NAS  
- Gestion caméra (offset X/Y)  
- Gestion des entités (sprites)

## VM / Programme Simple  
Format de script :  
```
draw_tile 10 5 3
wait_key A
set_gpio 12 1
play_sound 4
sync_cloud /user/data
```

# Guil-OS Rack — Architecture Modulaire RISC-V

Guil-OS Rack est une infrastructure informatique modulaire basée sur des cartes
RISC-V et RP2040, conçue pour offrir un système extensible, robuste et entièrement
piloté par un noyau minimaliste en assembleur RISC-V.

Ce projet combine :
- un OS maison (Guil-OS),
- des services Cloud/NAS sous Debian RISC-V,
- des modules utilisateurs RP2040,
- un rack matériel extensible (USB, SATA, PATA, PCMCIA, Audio, Écran).

---

## 🧠 1. Architecture Générale

Le rack est composé de trois cartes Milk-V Duo-S et de plusieurs modules RP2040 :

- **Duo-S #1 — Guil-OS Brain**
  - Noyau RISC-V (C906)
  - A53 désactivé
  - Scheduler, VM, moteur iso 2D
  - Gestion SPI/UART/I²C/GPIO
  - Orchestration des modules

- **Duo-S #2 — Cloud Board**
  - Debian RISC-V
  - API HTTP/HTTPS
  - Git/Teacup Sync
  - Base de données (SQLite/MariaDB)
  - Web Gateway

- **Duo-S #3 — NAS Board**
  - Debian RISC-V
  - Gestion HDD 3.5" SATA / SSD / M.2 / mSATA
  - Cache RAM + SSD
  - Streaming d’assets (tiles, sprites, maps)
  - RAID optionnel

- **Modules RP2040**
  - Screen Board (DVI/VGA/LCD via PIO)
  - Hub I/O (USB-A/C, PATA, SATA, PCMCIA)
  - Audio Daemon Hub (I²S/DAC/AMP)

---

## 🧱 2. Communication Inter-Cartes

Les cartes communiquent via un bus mixte :

- **SPI** : transfert rapide (framebuffer, assets)
- **UART** : commandes, événements, logs
- **I²C** : configuration, capteurs
- **GPIO** : interruptions, signaux parallèles (PCMCIA)

---

## 🖥️ 3. Modules RP2040

### Screen Board
- DVI/VGA/LCD via PIO
- Framebuffer + double buffering
- Commandes de dessin envoyées par Guil-OS

### Hub I/O Board
- USB-A/C via TinyUSB
- PATA/IDE via bus GPIO + logique externe
- SATA/mSATA/M.2 via ponts dédiés
- PCMCIA via bus parallèle
- HID → UART

### Audio Daemon Hub
- I²S / DAC / amplificateur
- Mixage musique + SFX
- Commandes PLAY/STOP/VOLUME via UART

---

## 💾 4. NAS Extensible (3.5" SATA)

Le NAS utilise :
- des ponts USB-SATA ou des contrôleurs SATA dédiés,
- des baies hot-swap 3.5",
- un cache RAM + SSD,
- Debian RISC-V pour la gestion des volumes.

Guil-OS accède aux assets via SPI ou HTTP.

---

## 🌐 5. Cloud Board

La carte Cloud fournit :
- API REST,
- synchronisation Git/Teacup,
- base de données,
- services réseau,
- éventuellement émulation x86 via Box86/Wine.

Fonctionnalités :

- VM de scripts

## 🧠 **Concept : Guil‑OS Rack Request Router (RR‑Board)**  
Le RR‑Board est un **serveur de requêtes** qui :

- reçoit les demandes du rack  
- les analyse  
- les route vers le bon module  
- gère les files d’attente  
- équilibre la charge  
- renvoie les réponses au Brain ou au module demandeur

C’est un **load balancer matériel**, un **dispatcher**, un **switch de processus**, un **proxy interne**.

# 🔀 **2. Fonction : Router / Dispatcher / Load Balancer**

Le RR‑Board gère :

### ✔ **Routing des requêtes**

- `/api/user/login` → Cloud Board

### ✔ **Queueing**
Tu peux implémenter :

- FIFO  
- priorité  
- round‑robin  
- weighted scheduling  
- time‑slice scheduling  
- load‑aware scheduling

### ✔ **Load Balancing**
Si tu as plusieurs modules identiques :

- plusieurs compute nodes  
- plusieurs NAS nodes  
- plusieurs cloud nodes  

Le RR‑Board distribue la charge.

### ✔ **Caching**
Le RR‑Board peut :

- cacher des réponses DB  
- cacher des assets  
- cacher des images  
- cacher des scripts  
- cacher des états du rack

### ✔ **Failover**
Si un module tombe :

- RR‑Board reroute vers un autre  
- ou renvoie une erreur propre à Guil‑OS

# 🧩 **3. Pipeline interne du RR‑Board**

```
[REQ IN] → [Parser] → [Classifier] → [Router] → [Queue] → [Backend] → [Response] → [REQ OUT]
```

### Modules internes :

- **Parser** → SPI/UART/HTTP  
- **Classifier** → DB / File / Image / Compute / Audio / Screen  
- **Router** → table de routage  
- **Queue Manager** → FIFO / Priority / RR  
- **Backend Connector** → drivers SPI/UART/HTTP  
- **Response Builder** → format Guil‑OS  
- **Logger** → NAS Board  
- **Monitor** → Cloud Board
